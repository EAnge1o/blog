How it works #

💡 idea→ ⚙ build from scratch→ 📦 ship to PyPI / npm→ ⏺ REC record→ ▶ PLAY · $0.00→ ⏩ diff what drifted→ CI ✅

同一条循环，既管 agent 的运行，也管造工具的人本身：record once, replay forever.
（本页没有 <script src>、没有 npm install、没有 dashboard —— 只有一个 .html 文件和一个 rAF 循环。）

The tape suite #

同一个“磁带”隐喻，钉在 agent 栈的三层边界上：

⏺ tapedeck

FLIGHT RECORDER · AGENT 层

把一次完整运行（每个模型调用、工具调用、usage）录成带版本号的 JSONL trace。改完代码离线逐字节重放，$0.00；一条命令 diff 出第一个漂移的步骤，退出码直连 CI。

pip install tapedeck-llm
PythonPyPI0 depspytest fixture

⏺ mcptape

TAPE RECORDER · MCP 边界

把任意 MCP server 包一层：录制一次，永久离线回放，diff 出协议层漂了什么。MCP 工具调用的飞行记录仪，与 tapedeck 同一套哲学。

pip install mcptape
PythonPyPI0 depsMCP

⏺ mocktape

MOCK SERVER · HTTP 层

一个配置文件生成带状态的 CRUD API；真实 API 录成可读 YAML 磁带离线回放；每个 404 给出最近匹配诊断；场景切换、故障注入、实时流量面板。

npm i -D @eange1o/mocktape
TypeScriptnpm75 kBdashboard

mocktape 管 HTTP 流量，tapedeck 管 agent 决策，mcptape 管 工具协议边界。如果 mock 的流程最终会调模型或 MCP server —— 三个一起用。

Honest boundaries #

  • 确定性重放只在咖啡层以下成立。 日程里未定种子的随机性，可能导致实际进度与录制内容产生偏差 —— 这是一切 record/replay 工具（VCR.py、respx，以及我）共同的下边界。
  • Roadmap 会漂移，且没有 changelog。 步骤随时增删；diff 的 exit code 2（structural drift）才是诚实信号。
  • From-scratch ≠ production-ready。 nimbus-* 用来理解原理，不是用来接生产流量的 —— 请勿把付款业务跑在 nimbus-chain 上。
  • 不在你背后 monkeypatch。 本页零 cookie、零追踪、零上报；你的“会话磁带”（如果按 REC）只存在于当前标签页内存里，刷新即抹带。
